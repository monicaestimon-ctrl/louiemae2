## Phase 6o — exact destination scope for modeled estimates

The saved delivery research uses representative destination ZIPs. A price observed or modeled for one ZIP must not authorize its entire three-digit region. Modeled parcel settings now accept `modeledZip5Zones`; when supplied, this map replaces prefix coverage, including when empty. Missing ZIPs require a quote even if `zip3Zones` contains their prefix. ZIP+4 uses the first five digits. Supplier-rate behavior is unchanged.

Configuration validates five-digit keys and requires each destination to point to an existing modeled weight table. Product/cart/checkout continue to share `groupFreight`, so they cannot disagree about this scope.

The private November 9 evidence packet contains ten sample lane tables, 72 billable-pound entries per lane, dated source hashes and the refreshed published 30.50% ground fuel benchmark. These are planning estimates, not account rates. The packet is prepared, not activated. No national coverage or publication is inferred from sample lanes. Rates must be installed with the approved allowance, processing, stock, margin and destination controls before checkout activation.

Validation: modeled configuration tests reject invalid ZIPs and missing tables; delivery integration checks exact ZIP/ZIP+4 acceptance, neighboring-ZIP rejection and an empty map disabling model coverage. No payments or supplier orders were submitted.
