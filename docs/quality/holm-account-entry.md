# HOLM account access without inventory

Account and sign-in routes are independent of the catalog subscription. An exhausted or unavailable catalog must not prevent customers from signing in, checking membership or signing out. The catalog recovery screen links to account access. Authentication must settle before any account screen is mounted, and viewer/role changes replace private account state.

Account screens remain interaction-loaded. The entry shell removes the decorative startup markup, owns private indexing, provides retail and HOLM navigation, and leaves the existing product eligibility guards intact. Anonymous account access skips private application reads. Google returns to the independent welcome route, while a validated stored trade return intent resumes after sign-in. Sign-out prevents duplicates, preserves local project drafts on failure and clears only the existing private trade keys after success.

Validation includes empty-catalog entry, authentication boundaries, safe return intents, OAuth destination, sign-out failure and success, deferred bundle boundaries, and mobile/landscape/desktop browser fixtures. Production verification must name the deployed commit and distinguish anonymous navigation from an authenticated business journey. No order, payment or supplier dispatch is part of this verification.

This phase does not activate inventory, publish unqualified products, change prices, complete the trade application/hub outage behavior, or establish full Lighthouse acceptance.
