# Public product HTML and response status

Product document requests read the same anonymous `products:getStorefrontDetail` projection used by the live storefront. No account token or private supplier record is used. The handler packages the built storefront HTML through Vercel's explicit `dist/index.html` function include.

The initial response contains the real product name, description, current public price, selected-option image and availability, canonical metadata and structured product data. Product image renditions are discoverable directly in HTML. Unknown options return 404 instead of silently selecting a different option. Missing products return 404; a failed query, timeout, invalid public response or missing build template returns a non-cacheable 503 with Retry-After. Out-of-stock listed products remain valid 200 documents with an unavailable state. Only GET and HEAD are accepted.

The initial document has no purchase controls. The live React detail query must complete before interactive purchasing appears; server checkout eligibility remains authoritative. While that query is pending, the matching read-only document remains visible. A completed, failed, or mismatched request removes it before the next paint. Navigation, startup failure and the default error boundary also remove it. The skip link targets the visible document during the handoff. Initial structured data is removed after the live handoff so it cannot describe an old price or route.

All catalog strings are escaped as text or attributes. Structured JSON escapes `<` to prevent script termination. HTML replacement callbacks preserve literal dollar sequences. Image URLs accept HTTPS or same-origin relative sources, and prepared derivatives require an exact immutable source match. Unselected multi-option products do not advertise a single specific Offer in structured data.

Validation includes malicious catalog text, exact option pricing, missing options, missing templates, invalid prices, response-status distinctions, anonymous query arguments, read-only initial content, and failed-query handoff. A local production-build browser check verified readable content with JavaScript disabled, one product heading after handoff, no page errors, and 404 status for missing products and options. The fixture uses anonymous production catalog reads and makes no commerce command.

This increment is limited to `/products/:id`. Collections, other unknown routes, sitemap generation, global security headers, production deployment verification and repeated route acceptance remain separate work. Single-run local diagnostics are not production acceptance.

The local combined candidate passed 225 test files (1,346 tests, one skip). Moving the API fixture out of the deployed api directory and the layout-only handoff correction also passed focused tests. The latest compressed local diagnostic retained zero mobile CLS and near-zero desktop CLS; both desktop products scored 100 Performance. Mobile scores were 93 and 95, with one failed live-readiness check. Reports remain in artifacts/lighthouse/2026-11-17T01-47-56-976Z. These are incomplete diagnostic results, not release acceptance. The earlier uncompressed and shifting runs are retained as failed evidence.

This catches module-resolution failures that bundled tests can hide; actual Vercel preview packaging still requires verification.
