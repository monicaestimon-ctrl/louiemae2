# Story image formats

The Story hero retains its original composition, dimensions, responsive sizes, alt text and WebP fallback. A source-hashed AVIF family is offered through matching initial-server and interactive picture markup. Supported browsers choose AVIF; unsupported browsers use the existing WebP candidates. An interactive AVIF failure removes the AVIF source and retries the WebP image once. If WebP also fails, the interactive page shows an accessible unavailable-image placeholder while preserving the known photo aspect ratio. Empty hero sources use the same placeholder. The hero component is keyed by source, so changing away and back starts a fresh attempt. Failures are classified using the selected image URL, including when AVIF is unsupported. The server AVIF source is enabled only when scripting is enabled; JavaScript-disabled browsers receive WebP, including when the AVIF file is corrupt.

The AVIF45/effort7 recipe operates on a losslessly oriented original, never a lossy intermediate. The source SHA256 and recipe determine immutable output names. `node scripts/prepare-story-avif.mjs` recreates the family; `node scripts/verify-story-images.mjs` checks the original hash, recipe-derived path, all rendition hashes, format, dimensions and smaller byte size than WebP at each matching width. Run the Story preparation after changing the original or rerunning the generic brand manifest generator. CI rejects a missing or stale AVIF mapping.

The 640px candidate is 55,052 bytes versus 111,322 bytes for the existing WebP, a 50.5% image-byte reduction. Source, WebP and AVIF were compared side by side at the displayed mobile size; composition and colors remain consistent. This is not a page-score claim.

The local browser fixture renders the actual server page document and StoryPage, with local site data and actual built CSS. Twenty-four cases cover 390/844/1440px at 1.75 device scale: normal AVIF, AVIF disabled, AVIF 404, both formats failing, WebP failing with AVIF disabled, corrupt AVIF, JavaScript disabled with corrupt AVIF, and an empty hero. The client script is held until the server picture candidates and sizes are inspected. Placeholder width and height are compared with the loaded photograph, and empty server/client geometry must match. CI retains all fixture screenshots. Healthy handoff fetches one hero asset; failure is bounded to one AVIF attempt from each server/client document and one WebP. No business requests are submitted. Final-head preview and production verification remain release requirements.
