# Reviewed retail checkout contract

This additive backend release is a prerequisite for the revised cart in PR #323. Deploy and verify it before merging that frontend consumer.

`retailLaunch.cartReview` reads one selected option using its public product ID, variant ID, requested selling quantity and a bounded retry attempt. Changing the attempt changes the Convex query identity, so a retry executes independently of a product page that retains its existing subscription. The return value contains only the public product detail, selected identity, requested quantity and a current quantity ceiling. Supplier SKU, wholesale cost, source documents and warehouse records are not returned.

Ashcroft's ceiling is the lesser of 20 and the current reconciled supplier quantity. Missing, expired or absent feed rows yield zero. Zuo requires current, verified available-to-sell evidence with a known warehouse and pack basis; piece quantities are converted through the verified pack size. On-hand-only, binary or unverified evidence does not become an automatic purchasing quantity. The returned source ceiling is not an inventory reservation. The existing authoritative checkout rechecks current evidence and internal commitments before creating an order intent.

The legacy Ashcroft checkout accepts an additive `reviewVersion: 1` contract. Each line supplies `reviewed.merchandiseMinor` and `reviewed.deliveryMinor`, both integer per-selling-unit USD cents. The mutation compares these with its own current merchandise and delivery calculation before inserting a checkout or reserving credit. A mismatch returns HTTP 409 with `PRICE_CHANGED`; no Stripe session is created. Matching client values never replace the server calculation. Missing or malformed fields on a versioned request are also rejected. Unversioned legacy clients retain the prior server-priced contract during rollout; the new cart always sends the reviewed version.

Credit reservations remain governed by the existing lifecycle: session-creation failure and verified session-expiration events release the hold idempotently. The legacy hourly safety net remains conditional on the existing credit version flag. A frontend balance update from its own reservation must not discard a successful checkout response; that consumer fix belongs to PR #323. A shopper abandoning a created Stripe session does not cause the browser to fabricate a release or payment outcome.

Validation uses synthetic database records and mocked Stripe only. Tests cover quantity 5 against stock 3, the Ashcroft ceiling of 20, unknown inventory, removed options, Zuo piece-to-pack conversion, on-hand rejection, merchandise/delivery price changes, malformed reviewed requests, matching server-priced totals and no credit hold on rejection. No production prices, stock, publication state, payments or supplier orders are changed by this release.

Review fixes: versioned requests project only the two validated reviewed amounts; unrelated client fields cannot turn into a false out-of-stock error. Each Ashcroft review shares one feed read across its public variant projection and selected ceiling, preserving the existing no-feed projection fallback. The response includes the feed validity deadline as `expiresAt` (null for non-Ashcroft/no feed); the dependent cart consumer invalidates and refreshes at that deadline and on return to a visible tab. Server checkout independently rechecks expiry.
